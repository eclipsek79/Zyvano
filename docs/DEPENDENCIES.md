## Workspace Structure

### pnpm Workspaces

```yaml
# pnpm-workspace.yaml
packages:
  - 'apps/*'
  - 'packages/*'
```

Workspace members:
- `apps/web` - Next.js web application
- `apps/mobile` - React Native/Expo mobile app
- `apps/desktop` - Tauri desktop application
- `packages/types` - TypeScript type definitions
- `packages/validation` - Validation schemas
- `packages/config` - Configuration utilities
- `packages/shared` - Shared utilities
- `packages/ui` - Shared React components
- `packages/api-client` - API client library
- `packages/media-contracts` - Media provider interfaces

### Dependency Ownership Rules

**Root (package.json)**
- Only monorepo-wide tooling
- Examples: turbo, typescript, eslint, prettier

**Application (apps/*/package.json)**
- Each app owns its own dependencies
- No hoisting of app-specific deps to root
- Apps may depend on workspace packages

**Shared Package (packages/*/package.json)**
- Owns all direct dependencies it imports
- Should use peer dependencies for shared libraries (e.g., React)
- Clearly document peer dependency requirements

**Backend (backend/pyproject.toml)**
- Owns all Python dependencies
- Never in root package.json
- Locked with backend/uv.lock

**Desktop (apps/desktop/src-tauri/Cargo.toml)**
- Owns all Rust dependencies
- Desktop TypeScript deps in apps/desktop/package.json
- Locked with Cargo.lock

## React Peer Dependency Handling

### Standard Peer Dependency Rules

React 19.1.0 is required for:
- React DOM: 19.1.0
- All React-based applications

Shared packages should declare:

```json
{
  "peerDependencies": {
    "react": "19.1.0",
    "react-dom": "19.1.0"
  },
  "peerDependencyMeta": {
    "react": { "optional": false },
    "react-dom": { "optional": false }
  }
}
```

### Handling Peer Warnings

A peer dependency warning is **NOT automatically a failure**.

**Valid scenarios for peer dependency meta**:
- UI component libraries may have `react` as optional
- Certain utility libraries work with multiple React versions

**Documented exceptions are tracked in**: `docs/react-peer-exceptions.json`

### Exception Documentation

```json
{
  "exceptions": [
    {
      "package": "@package/name",
      "issue": "Package X provides compatibility layer",
      "peerDependency": "react@19.1.0",
      "reason": "Library supports multiple React versions",
      "status": "verified",
      "verified_date": "2024-01-01"
    }
  ]
}
```

Only verified, documented exceptions are allowed.

## Lockfile Management

### pnpm-lock.yaml

**Rules**:
1. **Committed to Git** - Ensures reproducible installs
2. **Never manually edited** - Only pnpm should modify
3. **Reviewed in PRs** - Changes tracked and auditable
4. **Updated with dependencies** - `pnpm install` updates on dependency changes

**Installation**:
```bash
pnpm install --frozen-lockfile
```

### backend/uv.lock

**Rules**:
1. **Committed to Git** - Ensures reproducible Python environments
2. **Generated by uv** - Never manually edited
3. **Synchronized with pyproject.toml** - Run `uv sync` to update

**Installation**:
```bash
uv sync --locked --directory backend
```

### Cargo.lock

**Rules**:
1. **Committed to Git** - Essential for reproducible builds
2. **Managed by Cargo** - Never manually edited
3. **Updated with dependency changes**

**Building**:
```bash
cargo check --manifest-path apps/desktop/src-tauri/Cargo.toml --locked
```

## JSON-Based Dependency Inspection

### pnpm List as JSON

For structured dependency analysis:

```bash
# List all dependencies with full tree
pnpm list --json --recursive --depth Infinity

# List workspace-specific dependencies
pnpm list --json --filter @zyvano/types --depth Infinity

# Parse for analysis (use jq, Node.js, etc.)
pnpm list --json --recursive --depth Infinity | jq '.[]'
```

**Why JSON**:
- Reliable, parseable format
- No ambiguity with version specifiers
- Automatable validation
- Machine-readable for tooling

**Never rely on**:
- Human-readable console output
- Fragile regex matching on dependency names
- Text parsing of dependency trees

### Usage in Validation Scripts

```javascript
// scripts/validate-deps.mjs
const { execSync } = require('child_process');

const deps = JSON.parse(
  execSync('pnpm list --json --recursive --depth Infinity').toString()
);

// Structured validation
deps.forEach(workspace => {
  workspace.dependencies?.forEach(dep => {
    // Validate dependency versions, ranges, etc.
  });
});
```

## Conflict Resolution

### Peer Dependency Conflicts

If two packages require incompatible React versions:

1. **Document the conflict** in `docs/react-peer-exceptions.json`
2. **Determine compatibility** - Does one package have flexibility?
3. **Use exact versions** - Lock to compatible versions if possible
4. **Last resort**: Remove conflicting dependency or find alternative

### Transitive Dependency Conflicts

If transitive dependencies conflict:

1. **Identify the conflict** - Use pnpm's conflict resolution tools
2. **Pin explicit versions** in workspace package
3. **Document in comments**

Example:
```json
{
  "dependencies": {
    "some-lib": "1.0.0",
    "conflicting-dep": "2.0.0"  // Pinned to resolve transitive conflict with some-lib
  }
}
```

## Adding Dependencies

### Adding to an Application

```bash
cd apps/web
pnpm add some-package
# or
pnpm add --save-dev some-package
```

### Adding to a Shared Package

```bash
cd packages/ui
pnpm add some-package
```

### Adding to Python Backend

```bash
cd backend
uv pip install some-package
# Updates pyproject.toml and uv.lock
```

### Adding to Desktop Rust

```bash
cd apps/desktop/src-tauri
cargo add some-crate
# Updates Cargo.toml and Cargo.lock
```

## Updating Dependencies

### Checking for Updates

```bash
# pnpm
pnpm outdated

# Python
uv pip list --outdated

# Rust
cargo outdated
```

### Updating

```bash
# pnpm - update specific package
pnpm update some-package

# Python - update specific package
uv pip install --upgrade some-package

# Rust - update workspace
cargo update
```
